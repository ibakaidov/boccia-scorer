# ADR 0002: модель окон Electron

## Статус

Принято.

## Контекст

Приложению нужно окно оператора и отдельное табло на втором мониторе.

Старый проект уже использовал два окна Electron, но синхронизация была через общий небезопасный IPC-канал.

## Решение

Оставить два окна Electron:

| Окно | Роль |
|---|---|
| Operator | Управление матчем |
| Scoreboard | Read-only табло |

Окно табло не может менять состояние матча.

Состояние для табло передается через отдельный типизированный `ScoreboardState`.

## Последствия

Плюсы:

| Плюс | Объяснение |
|---|---|
| Подходит под второй монитор | Не нужен отдельный браузер или планшет |
| Контролируемая среда | Electron управляет окнами |
| Проще эксплуатация | Одно приложение открывает оба окна |

Минусы:

| Минус | Митигировать |
|---|---|
| Нужно следить за синхронизацией окон | Один typed state для табло |
| Нужно корректно восстанавливать окно табло | Main process пересоздает окно и отправляет последний state |
