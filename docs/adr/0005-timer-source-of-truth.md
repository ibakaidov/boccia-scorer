# ADR 0005: источник истины таймеров

## Статус

Принято.

## Контекст

Счетчик должен корректно считать использованное и оставшееся время. Для автономного режима восстановление незавершенного матча после перезапуска не требуется, но завершенный протокол должен хранить использованное время.

Старый компонент таймера хранил значение как использованное время, а отображал оставшееся время. Этот подход полезен, но должен быть формализован.

## Решение

Хранить в состоянии использованное время `elapsedSec` и лимит `maxSec`.

Оставшееся время вычислять:

```ts
remainingSec = maxSec - elapsedSec
```

В каждый момент времени активным может быть только один игровой таймер стороны.

## Последствия

Плюсы:

| Плюс | Объяснение |
|---|---|
| Протокол хранит использованное время | Это удобно для отправки результата |
| Подходит для истории матчей | Завершенный протокол хранит использованное время |
| Легко менять лимит | Оставшееся время пересчитывается |

Минусы:

| Минус | Митигировать |
|---|---|
| Нужно аккуратно учитывать реальное время между тиками | Использовать timestamp и fake-timer тесты |
| Частая запись на диск может быть дорогой | Throttling и обязательное сохранение на важных событиях |
