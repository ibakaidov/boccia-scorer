# ADR 0003: классы как настраиваемый справочник

## Статус

Принято.

## Контекст

В старом счетчике классы и часть правил были зашиты строками в код.

Это приводило к рискам: опечатки в `ТВС1/ВС2`, сложная смена времен, несоответствие актуальным правилам.

Пользователь отдельно отметил, что хардкод классов нежелателен.

## Решение

Хранить классы как справочник данных.

```ts
type GameClass = {
  id: string
  code: string
  nameRu: string
  ruleName: string
  kind: "individual" | "pair" | "team"
  endsCount: number
  endTimeSec: number
  ballsPerAthlete: number
  athletesPerSide: number
  active: boolean
}
```

Бизнес-логика использует параметры класса, а не строковые условия.

## Последствия

Плюсы:

| Плюс | Объяснение |
|---|---|
| Нет магических строк | Код не зависит от написания класса |
| Легко менять времена | Настройки редактируются на месте |
| Проще сверять с правилами | Дефолты отделены от логики |

Минусы:

| Минус | Митигировать |
|---|---|
| Нужна валидация справочника | Runtime validation и тесты |
| Можно случайно сломать настройки | Сброс к дефолтам и журнал изменений |
