# ADR 0004: offline-mode и синхронизация

## Статус

Принято.

## Контекст

На соревновании связь с сервером может пропасть. При этом матч нельзя останавливать.

Старый offline-mode был неполным. Пользователь подтвердил, что offline-mode и последующая синхронизация нужны.

При этом для малых соревнований не нужны игроки, регионы, команды и страны. Достаточно выбрать класс и вести стороны `Красные`/`Синие`.

## Решение

Реализовать offline-mode как штатный автономный режим без обязательной базы игроков. Минимальные локальные данные: настройки классов, времена и завершенные матчи в SQLite.

| Данные | Поведение offline |
|---|---|
| Игроки | Не требуются для автономного матча |
| Регион/команда/страна | Не требуются для автономного матча |
| Матч | Ведется локально |
| Отправка энда | Попадает в очередь |
| Завершение матча | Попадает в очередь, если сервер недоступен |

Если серверной базы нет, автономный матч все равно можно начать: нужен только класс.

Автономный режим без сервера является штатным сценарием, а не исключением.

## Последствия

Плюсы:

| Плюс | Объяснение |
|---|---|
| Матч не зависит от сети | Ведение продолжается offline |
| Не нужна база игроков | Малое соревнование можно провести сразу |
| Можно синхронизировать позже | Очередь хранит pending actions |

Минусы:

| Минус | Митигировать |
|---|---|
| Меньше данных в протоколе | Для малых соревнований протокол строится по цветам, без имен |
| Нужна идемпотентность сервера | `clientMatchId` и `clientEventId` |
| Возможны failed задачи | Экран очереди и retry |
