## Архитектура старого Electron

Старый `background.ts` создает два окна Electron.

Первое окно показывает операторский интерфейс.

Второе окно показывает `SideDisplay`.

Синхронизация между окнами идет через общий IPC-канал `asynchronous-message`. Main process просто пересылает сообщения во все окна.

## Состояние

Основное состояние хранится в Vuex:

| Поле | Назначение |
|---|---|
| `players` | Красный и синий игрок |
| `gclass` | Класс матча |
| `times` | Использованное время по игрокам и эндам |
| `score` | Счет по игрокам и эндам |
| `tieTimes` | Время тай-брейка |
| `tieScore` | Победитель тай-брейка |
| `end` | Текущий энд |
| `oneMinuteTimer` | Разминка или сбор мячей |
| `tenMinutesTimer` | Технический таймер |
| `referee` | Судья на корте |
| `refereeTimer` | Судья на счетчике |

## API старого проекта

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/check` | Проверка сервера |
| `GET` | `/players` | Получить игроков |
| `POST` | `/startMatch` | Начать матч |
| `POST` | `/sendEnd` | Отправить энд |
| `POST` | `/sendMatch` | Отправить матч |

Старый клиент ищет сервер на порту `2007`. Поиск сети завязан на hardcoded IP `192.168.1.5`, что нельзя переносить в v2.

## Настройки старого проекта

Старый проект хранит настройки времени в `Documents/timer.json`.

Дефолты старого проекта частично не совпадают с актуальными правилами 2025-2028 v.1.2.1. В v2 нужно использовать актуальные дефолты из правил, но разрешить редактирование на месте соревнования.

## Основные проблемы

| Проблема | Риск для v2 |
|---|---|
| Нет тестов | Нельзя безопасно менять таймеры и счет |
| Vue 2 и Vue CLI | Устаревший стек |
| Electron 11 | Устаревший Electron и Chromium |
| `nodeIntegration: true` | Высокий риск безопасности |
| Прямой импорт `ipcRenderer` в renderer | Нет границы безопасности между UI и Electron |
| Один общий IPC-канал | Нет типизации и валидации сообщений |
| Hardcoded IP | Приложение ломается в другой сети |
| Offline-mode неполный | При отсутствии сервера матч может быть невозможно начать |
| Хардкод классов | Ошибки при изменении правил или названий |
| Разное написание `ТВС1/ВС2` | Ошибка количества эндов |
| `name`/`fullName` конфликт | Риск падения UI и табло |
| Нет автосохранения матча | Потеря матча при сбое |

## Что переносить

| Переносить | Как переносить |
|---|---|
| Идею двух окон | Через современный Electron, preload и типизированный IPC |
| Основной flow матча | Переписать на Vue 3 и Pinia |
| Протокол матча | Формализовать модель данных и API |
| Настройки времен | Сделать справочник классов и настроек |
| Горячие клавиши | Реализовать явно и тестировать |

## Что не переносить

| Не переносить | Причина |
|---|---|
| `nodeIntegration: true` | Небезопасно |
| Общий IPC `asynchronous-message` | Нет типизации |
| Hardcoded IP | Непереносимо |
| Хардкод классов в условиях | Ломает поддержку правил |
| Hardcoded код `2007` | Должен быть настройкой/серверной политикой |
