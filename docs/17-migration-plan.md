# План миграции

Миграция означает не прямое переписывание файлов старого проекта, а перенос проверенных идей и исправление архитектурных проблем.

## Этап 1. База проекта

1. Создать проект `Vue 3 + Vite + Electron + TypeScript`.
2. Настроить strict TypeScript.
3. Настроить ESLint и Prettier.
4. Настроить Vitest.
5. Настроить Playwright.
6. Настроить два окна Electron.
7. Настроить preload и типизированный IPC.

## Этап 2. Доменные типы

1. Реализовать `GameClass` как справочник.
2. Реализовать `Match`, `Side`, `End`, `TieBreakEnd`; участников оставить опциональными server-mode метаданными.
3. Реализовать `TimerState`.
4. Реализовать `ScoreboardState`.
5. Добавить runtime validation.

## Этап 3. Настройки и справочники

1. Реализовать локальные настройки.
2. Добавить дефолтные классы из правил 2025-2028 v.1.2.1.
3. Добавить редактирование времен.
4. Добавить SQLite для истории завершенных матчей.
5. Добавить опциональный кэш серверных справочников.
6. Добавить сброс к дефолтам.

## Этап 4. Матч и таймеры

1. Реализовать store матча.
2. Реализовать таймеры с `elapsedSec`.
3. Реализовать счет по эндам.
4. Реализовать тай-брейк как массив дополнительных эндов.
5. Реализовать сохранение завершенных матчей в SQLite.
6. Реализовать журнал действий.

## Этап 5. UI оператора

1. Экран запуска.
2. Экран автономного старта матча: только класс.
3. Экран разминки.
4. Экран энда.
5. Экран тай-брейка.
6. Экран протокола.
7. Экран настроек.

## Этап 6. Табло

1. Создать отдельный renderer для табло.
2. Сделать режимы ожидания, разминки, энда, сбора мячей, тай-брейка и протокола.
3. Подключить обновления через IPC.
4. Проверить второй монитор.

## Этап 7. API и синхронизация

1. Описать новый API v2.
2. Реализовать API client.
3. Реализовать sync queue.
4. Реализовать idempotency через `clientMatchId` и `clientEventId`.
5. Реализовать отправку start/end/finish.
6. Реализовать обработку offline/online.

## Этап 8. Безопасность

1. Убрать прямой доступ renderer к Node.js.
2. Запретить произвольные файловые пути из renderer.
3. Валидировать IPC payload.
4. Настроить CSP.
5. Не требовать код/пароль в автономном режиме; в server-mode проверять только через серверную политику.

## Этап 9. Тесты

1. Unit-тесты доменной логики.
2. Тесты таймеров.
3. Тесты настроек классов.
4. Component-тесты UI.
5. Integration-тесты IPC/storage/API.
6. E2E полного матча.
7. E2E offline sync.

## Этап 10. Релиз

1. Сборка под Windows.
2. Сборка под Linux.
3. Сборка под macOS.
4. Smoke-test.
5. Документация эксплуатации.

## Миграционные риски

| Риск | Митигировать |
|---|---|
| Отличие старых времен от правил | Использовать актуальные дефолты и настройки |
| Новый сервер еще не готов | Mock server и adapter слой |
| Offline sync сложнее ожидаемого | Сначала реализовать локальную очередь и идемпотентность |
| Табло расходится с оператором | Один `ScoreboardState` и integration-тесты |
| Потеря завершенного результата | Сохранять завершенные матчи в SQLite |
