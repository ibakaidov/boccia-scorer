# Таймеры и счет

Таймеры и счет являются критической частью приложения. Их логика должна быть вынесена из UI-компонентов и покрыта тестами.

## Источник истины времени

В состоянии хранится использованное время `elapsedSec`.

Оставшееся время вычисляется:

```ts
remainingSec = maxSec - elapsedSec
```

Такой подход упрощает протокол, историю завершенных матчей и возможную серверную синхронизацию.

## Типы таймеров

| Таймер | Дефолт | Источник |
|---|---:|---|
| Разминка | 120 сек | Правила, раздел 10.1 |
| Красная сторона | зависит от класса | Правила, раздел 10.2 |
| Синяя сторона | зависит от класса | Правила, раздел 10.2 |
| Сбор мячей | 60 сек | Настройка приложения |
| Штрафной мяч | 60 сек | Правила, раздел 10.2.7 |
| Технический тайм-аут | 600 сек | Правила о technical time-out |

## Управление таймерами сторон

В один момент времени может идти только один игровой таймер стороны: красный или синий.

При запуске красного таймера синий должен остановиться.

При запуске синего таймера красный должен остановиться.

При паузе активный таймер останавливается без изменения счета.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Z` | старт/пауза красного таймера |
| `M` | старт/пауза синего таймера |
| `Space` | пауза активного таймера |
| `Enter` | подтверждение основного безопасного действия |
| `Esc` | закрыть диалог или отменить действие |

Клавиши изменения счета настраиваются отдельно, чтобы не конфликтовать с системной раскладкой и вводом в поля.

## Счет

Счет хранится отдельно по каждому энду.

```ts
type EndScore = {
  redScore: number
  blueScore: number
}
```

Общий счет вычисляется суммой по завершенным эндам.

```ts
redTotal = ends.reduce((sum, end) => sum + end.redScore, 0)
blueTotal = ends.reduce((sum, end) => sum + end.blueScore, 0)
```

## Изменение счета

Подтверждение каждого изменения счета не требуется.

Причина: во время матча оператору нужна скорость.

Защита от ошибок обеспечивается:

| Механизм | Назначение |
|---|---|
| Журнал действий | Можно увидеть, кто и когда изменил счет |
| Undo для последних действий | Желательно реализовать для счета и времени |
| Подтверждение отправки энда | Ошибки ловятся перед фиксацией энда |
| Ясная визуальная индикация | Оператор видит текущий счет и общий счет |

## Отправка энда

Отправка энда требует подтверждения.

Диалог должен показывать:

| Поле | Пример |
|---|---|
| Энд | `Энд 2` |
| Счет энда | `Красные 1 - 0 Синие` |
| Общий счет после энда | `Красные 3 - 1 Синие` |
| Использованное время | `Красные 02:34, Синие 03:01` |

Если сервер недоступен, энд сохраняется локально и попадает в очередь синхронизации.

## Тай-брейк

Тай-брейк запускается, если после основных эндов общий счет равный.

Тай-брейков может быть несколько. Поэтому модель должна хранить массив `tieBreaks`, а не один boolean.

Победитель определяется счетом тай-брейка. Если счет тай-брейка равный, создается следующий тай-брейк.

## Сохранение

Для автономного режима не требуется восстановление незавершенного матча после перезапуска. Обязательное хранение касается завершенных матчей.

Для server-mode и mixed-mode допустимо сохранять снимки активного матча, чтобы поддержать синхронизацию и восстановление, если это потребуется серверной логикой.

Рекомендуемые события сохранения для режимов с синхронизацией:

| Действие | Сохранять |
|---|---|
| Старт матча | Да |
| Изменение таймера | Да, с разумным throttling |
| Пауза таймера | Да |
| Ручная коррекция времени | Да |
| Изменение счета | Да |
| Смена энда | Да |
| Отправка энда | Да |
| Завершение матча | Да |

Для тика таймера не нужно писать на диск каждую секунду без ограничений. Допустимо сохранять раз в несколько секунд и обязательно при паузе/переходе.

## Восстановление

В автономном режиме восстановление незавершенного матча после перезапуска не является обязательным требованием.

В server-mode и mixed-mode приложение может проверять наличие незавершенного `activeMatch`.

Если матч найден, оператор должен выбрать:

| Действие | Описание |
|---|---|
| Восстановить | Продолжить матч с последнего снимка |
| Завершить технически | Закрыть матч после дополнительного подтверждения |
| Сбросить | Только с подтверждением и записью в журнал |
