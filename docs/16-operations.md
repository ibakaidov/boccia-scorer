# Эксплуатация на соревновании

Документ предназначен для оператора и организатора соревнования.

## Подготовка до соревнования

1. Установить приложение.
2. Подключить второй монитор.
3. Для большого соревнования настроить сервер; для малого соревнования включить автономный режим.
4. Синхронизировать справочники с сервером или использовать локальные дефолты классов.
5. Проверить классы, времена и корты.
6. Проверить дефолтные времена по правилам соревнования.
7. Проверить горячие клавиши.
8. Провести тестовый матч.

## Запуск

При запуске приложение должно показать:

| Поле | Что проверить |
|---|---|
| Сервер | Online или offline |
| Справочники | Дата последней синхронизации |
| Табло | Второе окно открыто |
| Очередь sync | Нет критичных failed задач |
| Незавершенный матч | Восстановить или закрыть по процедуре |

## Offline-mode

Offline-mode и автономный режим не требуют базы игроков.

В автономном матче игроки не выбираются. Оператор выбирает класс и ведет красную/синюю сторону.

Если сервер недоступен, официальный малый матч все равно можно начать по классу, потому что игроки не являются обязательными данными счетчика.

## Малое соревнование без сервера

Приложение должно поддерживать полный цикл малого соревнования без серверной части:

1. Выбрать или проверить класс матча.
2. Настроить корт при необходимости.
3. Провести матч по сторонам `Красные` и `Синие`.
5. Завершить матч без кода/пароля.
6. Сохранить результат локально в SQLite.
7. При необходимости позже синхронизировать результаты, если появится сервер.

## Во время матча

Оператор должен контролировать:

| Состояние | Где видно |
|---|---|
| Текущий энд | Верхняя панель и табло |
| Активный таймер | Цвет и статус таймера |
| Счет энда | Карточки сторон |
| Общий счет | Карточки сторон и табло |
| Статус синхронизации | Верхняя панель |

## Ошибка сети

Если сервер недоступен:

1. Матч продолжается.
2. Энд сохраняется локально.
3. Отправка добавляется в очередь.
4. Оператор видит статус `pending sync`.
5. При восстановлении связи приложение отправляет очередь.

## Перезапуск приложения

Если приложение было закрыто во время матча:

1. В автономном режиме восстановление незавершенного матча после перезапуска не требуется.
2. Завершенные матчи остаются в локальной истории SQLite.
3. В server-mode восстановление может быть добавлено отдельно, если это потребуется синхронизации.

## Завершение матча

Завершение требует:

1. Проверить минимальный протокол.
2. Подтвердить завершение.
3. В автономном режиме код/пароль не вводится.
4. В server-mode код/пароль вводится только если требует сервер.
5. Сохранить матч локально и отправить на сервер или в очередь при наличии server-mode.

## После соревнования

1. Проверить, что очередь синхронизации пуста.
2. Проверить failed задачи.
3. Экспортировать или передать логи, если это требуется организатору.
4. Не удалять локальные данные до подтверждения серверной стороны.
