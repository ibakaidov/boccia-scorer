# Обзор продукта

`Boccia Scorer v2` - десктопное приложение для ведения счета и времени в матчах бочча на соревнованиях.

Приложение должно работать надежно в условиях соревнования: ограниченное время, второй экран для зрителей и судей, возможные проблемы сети, необходимость быстро исправлять счет и время.

## Пользователи

| Пользователь | Задачи |
|---|---|
| Судья на счетчике | Настроить матч, управлять временем, вводить счет, отправлять результаты |
| Судья на корте | Контролировать ход матча и подтверждать решения |
| Организатор | Настроить классы, корты, сервер и синхронизацию при необходимости |
| Зрители и спортсмены | Видеть текущее время, счет, сторону и энд на табло |
| Разработчик | Поддерживать приложение, тесты, релизы и интеграцию с сервером |

## Основной сценарий

1. Оператор запускает приложение.
2. Приложение открывает два окна: окно оператора и окно табло.
3. Приложение синхронизирует справочники с сервером или работает автономно без сервера.
4. Оператор выбирает класс матча; красная и синяя стороны создаются автоматически.
5. Оператор запускает разминку.
6. Оператор ведет энды: таймеры красной и синей стороны, счет, сбор мячей.
7. Если после основных эндов счет равный, запускается тай-брейк.
8. Оператор проверяет минимальный протокол.
9. Оператор завершает матч; в автономном режиме код/пароль не нужен.
10. Приложение отправляет матч на сервер или кладет в очередь синхронизации.

## Границы продукта

Приложение не является системой управления турниром целиком. Оно отвечает за конкретный корт и конкретный матч.

Сервер является опциональным. Для больших соревнований сервер отвечает за базу спортсменов, справочники, расписание, хранение результатов и агрегированную отчетность. Для малых соревнований приложение должно работать без сервера, без базы игроков: достаточно класса матча и сторон `Красные`/`Синие`.

## Обязательные возможности

| Возможность | Требование |
|---|---|
| Два окна | Оператор и табло работают одновременно |
| Offline-mode | Матч можно вести без сервера: выбрать класс и вести красную/синюю сторону |
| Очередь синхронизации | Неотправленные матчи сохраняются и отправляются позже |
| История завершенных матчей | Завершенные матчи сохраняются локально в SQLite |
| Горячие клавиши | Управление таймерами и быстрыми действиями без мыши |
| Настройки | Классы, времена, горячие клавиши и серверные параметры редактируются на месте |
| Лог действий | Все важные действия оператора сохраняются для восстановления и разбора спорных ситуаций |

## Автономные малые соревнования

Для малых соревнований приложение должно быть самодостаточным.

Обязательные возможности автономного режима:

| Возможность | Описание |
|---|---|
| Минимальная настройка | Класс матча и стороны `Красные`/`Синие` |
| Локальные настройки | Классы, времена и корты хранятся локально |
| Импорт | Опционально: организатор может импортировать расширенные данные для больших соревнований |
| Редактирование справочников | Администратор соревнования может поправить классы, времена и корты на месте |
| Матч без сервера | Создание, ведение, завершение и сохранение матча не требуют сети |
| Корт | Не обязателен для старта автономного матча |
| Судьи | Не нужны в автономном режиме |
| Этап | Не нужен в автономном режиме |
| Код завершения | Не нужен в автономном режиме |
| Экспорт | Не нужен для малых соревнований |
| История | Завершенные матчи хранятся в SQLite |
| Поздняя синхронизация | Если сервер появится позже, локальные результаты могут быть отправлены |

Оператор автономного матча не выбирает игроков. Интерфейс должен позволять начать матч только по классу и цветам сторон.

Автономный режим не обязан восстанавливать незавершенный матч после перезапуска. Завершенные матчи должны сохраняться локально.

## Нефункциональные требования

| Требование | Описание |
|---|---|
| Надежность | Приложение не должно терять матч при падении или отключении питания |
| Скорость | Основные действия выполняются за один клик или одну клавишу |
| Читаемость | Табло видно с расстояния и при ярком освещении |
| Предсказуемость | Состояния `online`, `offline`, `pending sync`, `synced` явно видны оператору |
| Безопасность | Renderer не имеет прямого доступа к Node.js и файловой системе |
| Тестируемость | Таймеры, счет и синхронизация покрываются автоматическими тестами |
